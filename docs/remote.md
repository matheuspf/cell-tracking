## Machine and CUDA

Checked 2026-09-09, Vast instance `50386560`, Ubuntu 22.04.5:

- GPU: **RTX 4090, 24 GiB**, driver 575.64.03, CUDA toolkit 12.8.93.
  This SSH target is a 4090, despite the original expectation of a 3090.
- CPU: AMD EPYC 7713, 128 host threads visible; the container quota is
  **40.96 CPU equivalents**. Use the quota when choosing worker counts.
- Memory: **279 GiB** container limit; the host reports 503 GiB.
- Storage: **250 GiB container disk**. `/root` and `/kaggle` use this disk.
  It is not an independently attached persistent volume. Copy new work out
  before destroying or replacing the instance.

The native preflight passed four patterns across 8 GiB VRAM and 25 seconds of
4096-square cuBLAS multiplication with zero errors. PTX generated by the local
NVRTC 12.8.93 also loaded successfully. The older host's driver/storage failures
recorded under `work/remote-mirror/preflight-20260909/` do not describe this host.

The Vast image injects `/usr/local/cuda/lib64` into `LD_LIBRARY_PATH`, which
caused PyTorch CUDA initialization to fail. `scripts/root_remote_env.sh` removes
that entry, allowing the mirrored wheel to resolve its own CUDA libraries.
Other library-path entries are preserved. The setup applies to SSH command
shells, interactive bash/zsh, and the project launcher. When launching Python
from an independently managed process, source that script first.
